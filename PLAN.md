# План: переход в системное администрирование / DevOps


Я — Алексей, инженер-программист АСУ ТП / BMS (Niagara AX, Centraline, ПНР ОВиК). Цель изменилась: **системный администратор Linux → DevOps-инженер**. Автоматика остаётся козырем: опыт ПНР, работы с объектами и аварийками, роли «системный инженер АСУ ТП / SCADA» — запасной вход в IT.

Нагрузка: 6–10 ч/нед. Срок: ~30 недель. Неделя = теория + практика руками на стенде + вопрос как на собеседовании.

## Две контрольные точки

- **После этапа 4 (нед. ~17):** можно откликаться на «системный администратор Linux», «junior DevOps», «инженер техподдержки L2».
- **После этапа 7 (нед. ~30):** уверенный junior DevOps с проектом в GitHub.

## Этап 1. Linux (нед. 1–6) — идём здесь

| Нед. | Тема | Статус |
|---|---|---|
| 1 | Ubuntu Server, терминал, файловая система | ✅ |
| 2 | Пользователи, группы, права, sudo | ✅ |
| 3 | apt, процессы (`ps`, `kill`, сигналы, STAT), systemd, journalctl, своя служба | ✅ |
| 3 | **nginx**: установка, `ss`, `curl`, `nginx -t`, reload; + сайт в `sites-available`, reverse proxy | ⏳ сейчас |
| 4 | SSH по ключам, отключить вход по паролю, ufw, fail2ban | |
| 5 | Поиск неисправностей: journalctl, grep, конвейеры, `top`/load average, `df`/`du` (найти 3 внесённые поломки) | |
| 6 | Диски, разделы, LVM, монтирование, fstab, cron и systemd-таймеры, бэкап + восстановление | |

**Критерий:** с чистой ВМ за час — сервер с ключами, ufw, nginx, своей службой и бэкапом, без инструкции.

## Этап 2. Сети (нед. 7–10)

7. IP, маски, подсети (считать без калькулятора), `ip a`, `ip r`.
8. Маршрутизация, NAT, DNS (`dig`), DHCP — 3 ВМ в 2 подсетях, одна ВМ как роутер.
9. Диагностика: ping, traceroute, `ss`, tcpdump, Wireshark; HTTP изнутри (`curl -v`), TLS и сертификаты (Let's Encrypt / самоподписанный на nginx).
10. Файрвол (iptables/nftables поверх ufw), VPN WireGuard «офис — объект».

**Критерий:** поиск неисправности по шагам (адрес → маршрут → DNS → порт → служба), своя схема сети.

## Этап 3. Git, Bash, Python (нед. 11–14)

11. Git: commit, branch, merge, конфликт, GitHub, `.gitignore`. Все конфиги и скрипты стенда — в репозиторий.
12. Bash: переменные, условия, циклы, коды возврата, `set -euo pipefail`. Скрипт бэкапа с ротацией.
13. Python для админа: файлы, JSON, разбор логов, `requests` к HTTP API.
14. Python: скрипт-проверка «живы ли службы/сайты», логирование, аргументы CLI, запуск по таймеру.

**Критерий:** 3 скрипта в репозитории, каждый объясняю построчно.

## Этап 4. Docker и БД (нед. 15–17)

15. Docker: образ, контейнер, тома, сети, `docker logs/exec`. Отличие от ВМ.
16. Dockerfile для своего Python-скрипта, слои, размер образа, registry (Docker Hub / GitHub).
17. Docker Compose: nginx + веб-приложение + PostgreSQL; основы PostgreSQL (пользователи, бэкап `pg_dump`, восстановление).

**Критерий:** стенд поднимается `docker compose up` из репозитория < 15 минут.
➡ **Можно начинать отклики на сисадмина / junior.**

## Этап 5. Автоматизация (нед. 18–21)

18. Ansible: inventory, ad-hoc, playbook, идемпотентность.
19. Ansible: роли, переменные, шаблоны, vault. Плейбук, который делает «сервер этапа 1» с нуля.
20. CI/CD: GitHub Actions (или GitLab CI) — проверка скриптов, сборка Docker-образа, публикация.
21. CI/CD: автодеплой на ВМ (по SSH / Ansible) после merge в main.

**Критерий:** push в репозиторий → через несколько минут обновлённое приложение на сервере, без ручных действий.

## Этап 6. Облако и инфраструктура как код (нед. 22–24)

22. Облако (Yandex Cloud — бесплатный грант): ВМ, сети, группы безопасности, объектное хранилище.
23. Terraform: provider, resource, state, variables, outputs — поднять ВМ и сеть кодом.
24. Связка Terraform → Ansible → Docker: инфраструктура и настройка полностью из репозитория.

## Этап 7. Мониторинг, Kubernetes, выход на рынок (нед. 25–30)

25. Prometheus + node_exporter + Grafana, алерты в Telegram (Alertmanager).
26. Логи: Loki или ELK, поиск причины аварии по логам.
27. Kubernetes (k3s/minikube): pod, deployment, service, ingress, configmap/secret.
28. Kubernetes: Helm, деплой своего приложения, обновление и откат.
29. Итоговый проект + README со схемой; резюме (акцент: Linux, Docker, CI/CD, Ansible + опыт ПНР и аварийных ситуаций).
30. Тренировочные собеседования, 15–20 откликов, разбор отказов.

**Итоговый проект:** Terraform поднимает ВМ в облаке → Ansible настраивает → CI/CD собирает и деплоит приложение в Docker/k3s → Prometheus/Grafana следят → алерт в Telegram при падении.
