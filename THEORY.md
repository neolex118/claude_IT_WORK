## Неделя 1. Ubuntu Server, терминал, файловая система

> Конспект восстановлен по программе недели; подробные записи занятий остались в CLAUDE.md на домашнем ПК.

### Терминал
- Приглашение `user@host:~$`: кто, на какой машине, в какой папке; `$` — обычный пользователь, `#` — root.
- По приглашению всегда понятно, **где** ты: `vboxuser@CLAUDE:~$` — ВМ (bash), `PS C:\...>` — Windows PowerShell, `C:\...>` — Windows cmd.
- `Tab` — автодополнение, `↑` — история, `Ctrl+C` — прервать, `Ctrl+L` — очистить экран.
- Справка: `man <команда>` (поиск `/слово`, выход `q`), `<команда> --help`.

### Навигация и файлы
| Команда | Что делает |
|---|---|
| `pwd` | Где я |
| `ls -la` | Список с правами и скрытыми файлами |
| `cd /путь`, `cd ~`, `cd ..` | Перейти |
| `mkdir -p a/b` | Создать папки (с родителями) |
| `cp`, `mv`, `rm`, `rm -r` | Копировать, переместить, удалить |
| `cat`, `less`, `head`, `tail -f` | Читать файл |
| `nano` | Редактор (`Ctrl+O` сохранить, `Ctrl+X` выход) |

### Дерево файловой системы
| Папка | Что там |
|---|---|
| `/etc` | Конфиги системы и служб |
| `/var/log` | Логи |
| `/var/www` | Сайты |
| `/home/<user>` | Домашние папки |
| `/root` | Домашняя папка root |
| `/usr/bin`, `/usr/sbin` | Программы |
| `/tmp` | Временные файлы |
| `/dev`, `/proc` | Устройства и процессы как файлы |

Аналогия: `/etc` — папка с уставками, `/var/log` — журнал событий объекта.

## Неделя 2. Пользователи, группы, права, sudo

> Конспект восстановлен по программе недели.

### Пользователи и группы
- `id`, `whoami`, `groups` — кто я и в каких группах.
- `sudo adduser <имя>`, `sudo usermod -aG <группа> <имя>`, `sudo groupadd <группа>`.
- Учётки в `/etc/passwd`, группы в `/etc/group`, хеши паролей в `/etc/shadow`.
- Службы работают от своих системных учёток (`www-data`, `engineer`) — **принцип минимальных привилегий**.

### Права
`-rw-r--r-- 1 root root 26 index.html`
- Первый символ — тип: `-` файл, `d` папка, `l` ярлык (symlink).
- Дальше три тройки `rwx`: владелец, группа, остальные.
- Для файла: `r` читать, `w` менять, `x` запускать. Для папки: `r` видеть список, `w` создавать/удалять, `x` входить.
- Цифрами: `r=4, w=2, x=1`. `755` = `rwxr-xr-x`, `644` = `rw-r--r--`, `700` = `rwx------`, `600` = `rw-------`.
- `chmod 640 файл`, `chown user:group файл`.

### sudo
- Выполнить команду от root: `sudo <команда>`; кто может — группа `sudo`.
- Аналогия: «оператор» видит и запускает, «наладчик» меняет уставки — разные учётки с разными правами.

## Неделя 3. apt, процессы, systemd, journalctl, nginx

### apt
- `sudo apt update` — обновить список пакетов; `sudo apt upgrade` — обновить пакеты; `apt list --upgradable`.
- `sudo apt install <пакет>`; `already the newest version` — уже установлен.

### Процессы
- `ps -o user,pid,ppid,stat,cmd`, `ps --ppid <PID>` (потомки по родителю — PID короткоживущих процессов быстро устаревает), `ps -C <имя>`, `top`.
- PID — номер процесса, PPID — номер родителя. PID 1 — systemd.

**Состояния (STAT):**
| Буква | Значение |
|---|---|
| `R` | Выполняется / в очереди на CPU |
| `S` | Спит, ждёт события (норма для большинства) |
| `D` | Ждёт диск/сеть, сигналы не принимает, даже `-9` |
| `Z` | Зомби — завершился, родитель не забрал код |
| `s` | Лидер сессии |
| `+` | Передний план терминала |

**Сигналы:**
| Сигнал | Номер | Смысл |
|---|---|---|
| SIGTERM | 15 | Штатный останов (по умолчанию у `kill`) |
| SIGKILL | 9 | Снять ядром, без очистки — последнее средство |
| SIGHUP | 1 | Перечитать конфиг (`reload`) |

Порядок при зависании: подождать → `STAT` → журнал → `systemctl stop` → `kill -9`.

**Передний и фоновый план:** `команда &` — в фон (`[1] PID`), `jobs`, `fg %1`, `Ctrl+Z`, `bg`, `kill %1`.

### Коды возврата и связки команд
- У каждой команды код возврата: `0` — успех, иное — ошибка. Посмотреть: `echo $?`.
- `A ; B` — B всегда; `A && B` — B только если A успешна; `A || B` — B только если A с ошибкой.
- `nginx -t && systemctl reload nginx` — не применять битый конфиг; `cd /backup || exit 1` — не продолжать не в той папке.

### systemd
- Unit-файл службы: `/etc/systemd/system/<имя>.service`; пакетные — в `/usr/lib/systemd/system/`.
```ini
[Unit]
After=network.target        # только порядок запуска, не зависимость
[Service]
ExecStart=/usr/local/bin/villa1-heartbeat.sh
User=engineer
Group=villa1
Restart=always              # перезапуск после любого завершения
RestartSec=5
[Install]
WantedBy=multi-user.target  # куда ставится ярлык при enable
```
| Команда | Что делает |
|---|---|
| `systemctl start/stop/restart <служба>` | Управление сейчас |
| `systemctl reload <служба>` | Перечитать конфиг без остановки |
| `systemctl enable/disable [--now]` | Автозапуск (ярлык в `multi-user.target.wants`) |
| `systemctl daemon-reload` | Перечитать unit-файлы после правки |
| `systemctl status` | Состояние, PID, свежие логи |
| `systemctl cat` | Unit-файл + drop-in |
| `systemctl show -p X` | Загруженные значения (с умолчаниями) |
| `systemctl is-active` | Коротко: active / failed |

- `systemctl stop`: `KillSignal=15` → ждёт `TimeoutStopSec` (90 с) → SIGKILL; `KillMode=control-group` — всей группе с потомками.
- `ExecStartPre` — команда перед запуском (у nginx — `nginx -t`).
- Длинный вывод открывается в `less`; без него: `--no-pager -l`.

### journalctl
- `journalctl -u <служба>`, `-n 50`, `-f`, `--since "10 min ago"`, `-b`, `-xeu <служба>`.
- Формат: `дата хост источник[PID]: сообщение`; `systemd[1]` — пишет systemd, иначе — сама служба.

### Сеть: кто слушает порт
- `sudo ss -tlnp` — TCP, слушающие, числами, с процессами.
- `0.0.0.0:80` — все IPv4-адреса, `[::]:80` — все IPv6, `127.0.0.1:9000` — только локально.
- `curl -I http://localhost` — только заголовки; `curl.exe` в PowerShell.

### nginx
- Конфиги: `/etc/nginx/nginx.conf`; сайты — `sites-available/` (склад), `sites-enabled/` (ярлыки на включённые; подключаются только они).
- Включить: `sudo ln -s /etc/nginx/sites-available/<сайт> /etc/nginx/sites-enabled/`; выключить: `sudo rm /etc/nginx/sites-enabled/<сайт>`.
- Логи: `/var/log/nginx/access.log`, `error.log`, свои — через `access_log`.
- **master** (root) — открывает порт < 1024, читает конфиг, управляет worker. **worker** (`www-data`) — обрабатывают запросы, по одному на ядро (`worker_processes auto`).
- **Правило работы:** `sudo cp конфиг ~/конфиг.bak` → правка → `sudo nginx -t && sudo systemctl reload nginx` → проверка `curl`.
- `reload` — master тот же, worker новые, без простоя; битый конфиг master отклоняет. `restart` — полная остановка; с битым конфигом nginx не поднимется.

**Свой сайт с reverse proxy:**
```nginx
server {
    listen 8081;
    root /var/www/villa1;
    index index.html;
    access_log /var/log/nginx/villa1.access.log;

    location /app/ {
        proxy_pass http://127.0.0.1:9000/;   # «/» в конце — отрезать префикс /app/
    }
}
```
- **Reverse proxy**: клиенты ходят только к nginx, он передаёт запрос приложению на внутреннем порту. Одна точка входа, HTTPS и логи в одном месте, приложение не торчит наружу. Приложение слушает `127.0.0.1`.

**Диагностика по ответу:**
| Что видим | Значит | Где искать |
|---|---|---|
| `Could not connect` | Порт никто не слушает | Служба, `listen`, файрвол |
| `404 Not Found` | nginx ответил, файла нет | `root`, путь |
| `502 Bad Gateway` | nginx жив, приложение нет | `error.log` (upstream), `ss`, приложение |

### Проброс портов VirtualBox (NAT)
- ВМ за NAT не видна с хоста; правило «порт хоста → порт гостя»: `127.0.0.1:2222 → 22`, `127.0.0.1:8080 → 80`.
- Делается **на хосте**: PowerShell `& "<путь>\VBoxManage.exe" controlvm CLAUDE natpf1 "web,tcp,127.0.0.1,8080,,80"` (в cmd — без `&`) или в GUI: Настройки → Сеть → Проброс портов (не забыть OK).

## Неделя 4. SSH-ключи, ufw

### Вход по ключу
- `ssh-keygen -t ed25519 -C "подпись"` создаёт пару: `id_ed25519` (закрытый) и `id_ed25519.pub` (открытый).
- Открытый ключ кладут на сервер в `~/.ssh/authorized_keys` — список «кого пускать», одна строка на ключ.
- При входе сервер проверяет, что у клиента есть закрытый ключ, подходящий к открытому; сам закрытый ключ по сети не передаётся.
- Парольная фраза (passphrase) шифрует закрытый ключ на диске.
- Ключ создаётся на **каждом** компьютере, с которого входишь.
- В Windows нет `ssh-copy-id`:
  ```
  type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh -p 2222 user@127.0.0.1 "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
  ```

- Закрытый ключ — на клиенте, открытый — на сервере. Кража `.pub` не опасна; кража закрытого ключа = вход на все серверы с этим `.pub` (защита — passphrase; действия — удалить ключ из `authorized_keys` везде, выпустить новый).
- Права: `~/.ssh` — `700` (`drwx------`), `authorized_keys` — `600` (`-rw-------`). При слишком открытых правах sshd (`StrictModes yes`) игнорирует ключ.
- Добавить passphrase к существующему ключу: `ssh-keygen -p -f <путь>`.
- `ssh-keygen` спрашивает путь: Enter = путь по умолчанию в скобках; просто имя файла = относительный путь (текущая папка).
